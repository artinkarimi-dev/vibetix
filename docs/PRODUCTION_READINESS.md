## Operating boundaries

`ALLOW_SIMULATED_PAYMENTS=false` is the default. Enabling it does not connect a real gateway. The real provider interface is a design boundary and requires an asynchronous payment state machine; do not call a gateway while holding the current inventory transaction lock. Order status transitions implemented today are CONFIRMED/FAILED for the local provider, not a pretend complete payment lifecycle.

`EMAIL_TRANSPORT=disabled` leaves outbox messages pending; local capture records LOCAL_CAPTURED rather than SENT. The outbox processing transaction and idempotent local artifact are appropriate to local capture. A network provider requires bounded delivery timeouts, delivery idempotency, durable leases, retry classification and crash recovery verification.

The migration and non-destructive seed run in local Compose startup for convenience. Production should use a separate controlled migration job and reviewed catalog import, not run seed on every application start. Production PostgreSQL must not use the bundled optional test runtime. Docker and the remote CI workflow have not been executed on this host.

API list sizes are bounded. The account order/ticket list returns the newest 100 confirmed orders; direct owner-checked order lookup supports older order links. Seat inventory uses section filtering and bounded pagination. Catalog bootstrap is designed for this small catalog; larger deployments need paginated discovery/search and server caching with explicit invalidation. Session expiration is absolute, not sliding; re-authentication is the current refresh strategy.

Keep the PostgreSQL/event lock protocol consistent in every inventory writer. Do not bypass it with ad hoc admin SQL. The unique event-seat order item remains a database backstop against duplicate sale. Archive/refund/cancellation flows must preserve those financial and inventory invariants when implemented.
