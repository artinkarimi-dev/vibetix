# HTTPS and reverse proxy readiness

Local HTTP development remains supported with its separate non-Secure cookie. Production config requires a canonical HTTPS origin; session cookies use `__Host-vibetix`, Secure, HttpOnly, SameSite Strict, path `/` and no Domain. Unsafe API requests still require the exact allowed Origin. Do not disable origin checks to make a proxy work.

`frontend/https.conf.example` is an nginx TLS template for a reviewed certificate chain/private key and canonical hostname. It listens unprivileged on 8443, disables TLS session tickets, permits TLS 1.2/1.3 and supplies CSP, nosniff, frame protection, referrer and permissions policies. HSTS is enabled on HTTPS only, without includeSubDomains/preload; enable those only after reviewing all subdomains. The template also listens on unprivileged 8080 for a canonical 308 HTTPS redirect; production Compose maps host 80/443 to 8080/8443. Replace the example hostname in both servers; the template does not provision DNS, certificates/renewal, ACME or an edge load balancer.

`deploy/compose.production.yml` is a separate foundation example, not an override that accidentally inherits local HTTP/simulation credentials. Supply reviewed immutable app image digests and private secret file mounts. It uses external managed PostgreSQL/Redis. Migrator/bootstrap credentials are deliberately absent; run a protected migration job before rollout. Payments remain disabled; production is not approved for real sales.

The example gives nginx a fixed dedicated container IP, trusted by the API as `/32`; nginx overwrites forwarded headers. Adapt the subnet if necessary and restrict access to backend port 3001 to that proxy/controlled workers. Do not publish the backend port. If another edge sits in front of nginx, define/test its trust boundary before using forwarded client addresses. Never configure generic `trustProxy=true` or trust arbitrary request headers.

CSP restricts scripts/connections to self and forbids objects/framing/external form targets; inline styles remain needed by current components. `upgrade-insecure-requests` is HTTPS-only. This is not a nonce-based style policy or a guarantee against XSS. API responses remain no-store; preserve this through CDN/cache configuration. Validate deep links, content types, cache headers and stale chunk behavior after rollout.

File-backed Compose secrets retain host permission constraints. Ensure non-root nginx can read its private key without making it publicly readable; use a platform secret mount/controlled group. Add provider-specific CA mounts for database/Redis if not publicly rooted. Test full certificate/hostname verification and renewal/rollover, redirect/cookie behavior, response headers and client-IP budgets from outside the actual edge. Do not merely trust the `APP_ORIGIN` string as proof of transport.

The later [pre-production validation](PREPRODUCTION_VALIDATION_REPORT.md) executed native nginx and local-CA HTTPS, including actual headers, redirects, cookies and forwarding. All HTTP temporary paths are under `/tmp`; nginx owns public security policies and suppresses conflicting upstream copies. Docker images, public TLS, certificate renewals, private-network isolation and platform readiness checks remain unverified. The production template disables an incompatible HTTP healthcheck; configure certificate-aware external readiness before deployment.
